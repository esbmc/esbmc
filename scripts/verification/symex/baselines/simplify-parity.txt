# R28 -- both legs of one input, one mechanism: --no-simplify leaves calloc's
# constant total_size unfolded, so the memset takes __memset_impl's byte-wise
# loop instead of the folded path, and the test's --unwind 1 truncates it.

# memcleanup adds --no-unwinding-assertions, so the truncation becomes an
# assume(false) that cuts every path and the leak claim passes vacuously --

# bound past the 800-byte memset (--unwind 801) reports the leak again, on

#
# memsafety keeps unwinding assertions on, so the same truncation surfaces
# honestly as "unwinding assertion loop 4" in __memset_impl -- SUCCESSFUL ->
# FAILED, the sound direction.
#
# An --unwind calibrated against the simplified program is not a bound for the
# unsimplified one, so this is partly a premise failure of the relation. It is
